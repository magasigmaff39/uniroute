## 2. Problem & Solution

### Problem

- Информация о поступлении разбросана по официальным сайтам вузов, программ грантов и олимпиад. Правила отличаются по странам.
- Абитуриенту нужно одновременно учитывать много параметров: GPA, IELTS/SAT/ЕНТ, бюджет, дедлайны, гранты, активности, эссе и портфолио.
- Трудно самостоятельно оценить свой профиль относительно порогов конкретного вуза.
- Выбрать направление и вуз мешает большое число вариантов без объяснения, почему они подходят.
- После выбора нет понятного следующего шага и плана по срокам.

### Solution

1. **Профиль.** Пользователь проходит тест из 7 шагов.
2. **Анализ.** Система оценивает готовность по 4 осям (академика, язык, портфолио, финансы), сильные стороны и риски.
3. **Релевантные варианты.** Для каждого из 91 заведения считается соответствие профилю и примерный шанс. Список делится на уровни Safety / Target / Dream.
4. **Объяснение.** У каждой рекомендации есть причины («почему подходит») и факторы шанса с весами.
5. **Сравнение.** Выбранные вузы сравниваются по шансу, финансам, порогам, условиям жизни, дедлайнам, программам, преимуществам и рискам.
6. **Roadmap.** План строится по экзаменам, документам, эссе, активностям и подаче, с дедлайнами выбранных вузов.
7. **Действия.** Roadmap и дедлайны превращаются в задачи. На главном экране выделен следующий шаг по профилю, а во вкладке «Анализ → Ближайший шаг» — первая невыполненная задача roadmap.

UniRoute — это **персональный admission journey**, а не чат-бот и не каталог:
- ранжирование, шансы, план и следующий шаг вычисляются правилами из профиля;
- AI-ассистент — дополнительный слой пояснений поверх этих результатов.

## 5. System Architecture

**Общий поток:** `User → Frontend (React SPA) → Rule-based logic (shared/logic, engine.ts) ⇄ Backend API (Express) → AI (Gemini / Groq) · Data (Firestore / SQLite, статические базы) · External (RSS, SMTP, Firebase Auth) → Personalization → Result`

```
┌─ Браузер ──────────────────────────────────────────────────────────┐
│ React 19 SPA (Vite 8, Tailwind CSS 4)                              │
│  ├─ UI: тест -> диагностика -> подбор -> сравнение -> roadmap      │
│  ├─ rule-based логика: src/utils/engine.ts + shared/logic/*.js     │
│  │    статические базы shared/data: 91 заведение, 49 олимпиад      │
│  ├─ localStorage: профиль (admitroute_profile)                     │
│  └─ src/lib/api.ts -> HTTPS /api/*  (Authorization: Bearer)        │
└─────────────────────────────────┬──────────────────────────────────┘
                                  │
┌─ Firebase Hosting ──────────────┴──────────────────────────────────┐
│ dist/ (SPA) + security headers                                     │
│ /api/** -> rewrite в Cloud Function; prod-сборка вызывает          │
│ URL функции напрямую (VITE_API_URL)                                │
└─────────────────────────────────┬──────────────────────────────────┘
                                  │
┌─ Cloud Function `api` ──────────┴──────────────────────────────────┐
│ 2nd gen, europe-west1, Node 22, 1 GiB, timeout 180 s               │
│ Express 5 (server/app.js)                                          │
│  ├─ middleware: CORS -> JSON limits -> optionalAuth -> rate limit  │
│  ├─ routes: auth, universities, ai, tasks, documents,              │
│  │          portfolio, olympiads, mail, news, planner              │
│  ├─ services/llm.js -> Gemini API (основной) | Groq API (резерв)   │
│  ├─ db/store.js -> Cloud Firestore (prod) | SQLite (локально)      │
│  ├─ storage/files.js -> Cloud Storage | Firestore | диск           │
│  └─ внешние: Google News RSS, YouTube RSS, Gmail SMTP,             │
│              Firebase Auth, Secret Manager                         │
└────────────────────────────────────────────────────────────────────┘
```

| Слой | Технология | Роль | Взаимодействие |
|---|---|---|---|
| **Frontend** | React 19, TypeScript, Vite 8, Tailwind CSS 4 | Экраны пути, состояние профиля, локальные расчёты | Импортирует `shared/logic` и `shared/data`, вызывает `/api/*` |
| **Business / matching logic** | JS-модули `shared/logic` (chance, match, portfolioMatch, dates) и `src/utils/engine.ts` | Соответствие, шанс, диагностика, roadmap, следующее действие, дедлайны | Одни и те же модули работают в браузере и на сервере: `shared/` копируется в Cloud Function |
| **Backend** | Node.js 22, Express 5 | REST API, авторизация, хранение, прокси к AI и внешним источникам | Cloud Function `api`; локально — `node server/index.js` на порту 3001 |
| **Database / storage** | Cloud Firestore; SQLite через встроенный `node:sqlite`; Cloud Storage for Firebase | Пользователи, сессии, профили, задачи, портфолио, планировщик, документы, кеш | Абстракция `server/db/store.js` выбирает драйвер; файлы идут через `server/storage/files.js` |
| **AI layer** | `server/services/llm.js` → Gemini REST API; резерв — Groq (OpenAI-совместимый API) | Тексты вердиктов, разборов, отзывов, чат, резюме документов, переводы | Вызывается только с сервера; ключи — в Secret Manager |
| **API layer** | 10 групп маршрутов `/api/*` | Единая точка доступа клиента к данным и AI | Bearer-токен, rate limit, валидация ввода |
| **Authentication** | Собственные сессии (scrypt, bearer-токены) и Firebase Authentication (Google Sign-In) | Вход, регистрация, опциональный OTP | ID-токен Google проверяется на сервере через Firebase Admin SDK |
| **External services** | Google News RSS, YouTube RSS, Gmail SMTP (nodemailer), Google Fonts | Новости, видео вузов, письма, шрифты | Кеш: новости 60 мин, соцсигналы 12 ч, переводы 30 дней |

**Альтернативный деплой:** `vercel.json` + `api/index.js` (Vercel). Основной деплой — Firebase.

## 7. AI / Models

### Модели

| Модель | Provider | Где используется |
|---|---|---|
| Уровень **fast**: `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite`, `gemini-3-flash-preview`, `gemini-3.5-flash` (перебор по списку) | Google (Generative Language API `v1beta`) | Вердикт теста, чат, перевод, резюме документов, память чата, ремонт JSON |
| Уровень **smart**: `gemini-3-flash-preview`, `gemini-3.5-flash`, `gemini-3.6-flash`, `gemini-3.7-flash`, `gemini-3.8-flash`, … | Google | Разбор сравнения, эссе, портфолио, олимпиады, новости и соцсигналы |
| Уровень **deep**: `gemini-3-flash-preview`, `gemini-3.8-flash`, `gemini-3.5-flash`, … | Google | Анализ профиля, серверный эндпоинт сравнения |
| `openai/gpt-oss-120b` (smart / deep), `openai/gpt-oss-20b` (fast) | Groq | Резерв при ошибке или таймауте Gemini |
| `whisper-large-v3-turbo` | Groq | Только `POST /api/ai/transcribe`; в интерфейсе не используется |

Полный список моделей по уровням — в `server/config.js`.

**Механика `server/services/llm.js`:**
- перебор моделей уровня;
- пауза для сбойной модели на 10 минут;
- дублирующий запрос, если ответа нет 5 секунд;
- переход на Groq;
- разбор JSON с одним проходом ремонта;
- потоковая выдача.

В ответе API указываются `model` и `provider`. Без ключей AI-эндпоинты возвращают `503 AI_NOT_CONFIGURED`.

### AI-компоненты

| Компонент | Эндпоинт | Вход | Выход | Как используется дальше | Ограничения |
|---|---|---|---|---|---|
| Краткий вердикт | `POST /api/ai/quick-verdict` | Профиль | Вердикт и фокусы | Показывается в результате теста, кешируется в браузере | Если AI недоступен, показывается сообщение «офлайн» |

## 9. University Recommendation Logic

`User Profile → Matching Criteria → Candidate Universities (91) → Filtering / Matching → Final Recommendations`

Используется **прозрачная балльная модель на правилах**. Машинного обучения нет, модель не обучалась на данных.

### Критерии соответствия

База — 70 баллов. Функции `rawFit` в `shared/logic/match.js` и `matchUniversities` в `src/utils/engine.ts` используют одинаковые веса:

| Критерий | Вклад |
|---|---|
| Категория совпадает с треком / не совпадает | +20 / −30 |
| Школа для 7–8 класса, колледж для 9 класса | +15 |
| Направление входит в `supportedMajors` вуза | +15 |
| Регион выбран пользователем | +10 |
| GPA − порог: ≥ 0.3 / ≥ 0 / ниже порога | +10 / +5 / −15 |
| IELTS − порог: ≥ 0.5 / ≥ 0 / ниже порога | +8 / +4 / −12 |
| SAT (если у вуза есть порог): ≥ порог + 50 / ≥ порог / не сдан / ниже порога | +10 / +5 / −10 / −15 |
| ЕНТ (если у вуза есть порог): ≥ порог + 15 / ≥ порог / не сдан (вуз в Казахстане) | +10 / +5 / −5 |
| Олимпиада республиканского или международного уровня | +15 при доле принятых ≤ 20 %, иначе +6 |
| Климат, безопасность района ≤ 5, халяль-питание | от −4 до +4 |
| Бюджет «только грант»: полный грант есть / нет и стоимость > $5 000 | +10 / −40 |
| Бюджет до $5 000: стоимость ≤ $5 000 или есть грант / иначе | +5 / −20 |

### Ограничения, фильтрация и итог

- **Балл соответствия** на экране ограничен диапазоном **45–98**. Порядок полного списка «Подбор» определяется ключами: сначала заведения выбранного трека, затем выбранных регионов, затем неограниченный балл и примерный шанс. Поэтому одинаковые 98 % на экране не мешают списку реагировать на изменения профиля. Доступны фильтры по категории, уровню (Dream / Target / Safety) и региону.
- **Автоподбор** (`pickTargetUniversities`) работает в три шага:
  1. отбирает пул по треку;
  2. сужает его до выбранных регионов, если там хватает вариантов;
  3. сортирует по неограниченному баллу и набирает квоты по уровням: для трёх вузов — 1 Target, 1 Safety, 1 Dream.
- **Уровень** (Dream / Target / Safety) везде берётся из единой функции `estimateChance`.

### «Why this fits»

- `fitReasons()` собирает сработавшие причины: «есть ваше направление», «выбранный регион», «есть 100 % грант», «шанс ≈ N %».
- Поле `whyItFits` из базы дополняется упоминанием финансирования, если бюджет ограничен.
- Для 13 заведений в `engine.ts` заданы шаблонные тексты, в которые подставляются GPA, IELTS или ЕНТ пользователя.
- Факторы шанса выводятся с весом и пояснением.

### Отсутствующие данные

| Нет данных | Как обрабатывается |
|---|---|
| IELTS | В соответствии считается как 5.5; если отмечено «есть», но балл не введён — 6.0. В шансе — фактор −18, для казахстанских школ и колледжей −2 |
| SAT | 0 при подсчёте соответствия; в шансе −22, если SAT обязателен, или −6, если опционален |
| ЕНТ | В шансе −15 для казахстанских вузов, −4 для остальных |
| Целевые вузы в тесте | Система предлагает тройку и помечает её источник как `auto`; свой список пользователя не перезаписывается |
| Почти пустой профиль | Логика не падает и возвращает список. В контрольном прогоне: три варианта уровня Dream с ~13 % |

## 10. Admission Chance / Profile Assessment

**[Implemented]** `shared/logic/chance.js` → `estimateChance(profile, university)`

| Шаг | Формула / правило |
|---|---|
| Вход | GPA, IELTS, SAT, ЕНТ, олимпиады, активности, направление, бюджет; у вуза — пороги, доля принятых, тестовая политика, гранты, стоимость |
| База | `p = clamp(8 + acceptanceRate × 0.9, 5, 85)` |
| Факторы | GPA от +12 до −25 · IELTS от +10 до −28 · SAT от +14 до −24 · ЕНТ от +16 до −18 · олимпиады от +22 до −6 · активности от +12 до −10 (с большим весом для США/Канады и вузов с интервью) · направление +4 / −8 · финансы: +3, −6, −18, −30 |
| Итог | `p = clamp(p + Σ × (p < 30 ? 0.7 : 1), 2, 96)` |
| Уровень | Dream < 30 % · Target 30–59 % · Safety ≥ 60 % |
| Проекции | `estimateWithProjections`: оценка при целевом балле IELTS, SAT или ЕНТ (карточка вуза, сравнение) |
| Отображение | «~N %», бейдж уровня и список факторов с весом и текстом, например «IELTS 6.5 ниже порога 7.0 на полбалла» |

**Диагностика профиля** (`runDiagnostic`):
- **академика:** GPA / 4 × 80 + бонус SAT или ЕНТ, в пределах 30–100;
- **язык:** по диапазонам IELTS; без сертификата — 45;
- **портфолио:** 40 + уровень олимпиад + 10 за каждую активность (не больше +25);
- **финансы:** зависит от бюджета;
- **общий балл:** 0.35 × академика + 0.25 × язык + 0.25 × портфолио + 0.15 × финансы.

> **Ограничения метода.**
> - Это **ориентировочная эвристическая оценка** по опубликованным порогам и доле принятых. Она **не обучена и не проверена на реальных исходах приёма**, поэтому **не является математически точным прогнозом**.
> - Оценка **не гарантирует поступление** и **не заменяет решение приёмной комиссии**.
> - Значения ограничены диапазоном 2–96 %, поэтому крайние значения — это ориентир уровня, а не вероятность.

## 15. Security & Privacy

Перечислены только меры, которые есть в коде **[Implemented]**:

| Мера | Реализация |
|---|---|
| Защита API-ключей | Ключи Gemini и Groq используются только на сервере; клиент не обращается к AI-провайдерам напрямую |
| Переменные окружения | `.env` локально; `.env*`, `functions/.env*`, `functions/.secret.local` исключены в `.gitignore`; в репозитории только `.env.example` без секретов |
| Управление секретами | Firebase Secret Manager: `GEMINI_API_KEY`, `GROQ_API_KEY`, `GMAIL_APP_PASSWORD` (`defineSecret`, `npm run secrets:set`) |
| Аутентификация | Пароли — scrypt со случайной 16-байтной солью, сравнение `timingSafeEqual`. Сессии — случайные 256 бит, в БД хранится только SHA-256 хеш, срок 30 дней. Google Sign-In — `verifyIdToken(idToken, true)`. OTP хранится в виде хеша |
| Авторизация | `requireAuth` на маршрутах `tasks`, `documents`, `portfolio`, `planner` и защищённых `auth`; каждая запись привязана к `userId` |
| Доступ к БД | Правила Firestore запрещают прямой доступ клиента (`allow read, write: if false`), всё идёт через сервер и Admin SDK |
| Ограничение нагрузки | Rate limit в минуту: общий 240, AI 30, auth 20, upload 30 |
| Файлы | Whitelist MIME, сверка с сигнатурой (magic bytes), до 15 МБ, безопасные пути хранения |
| HTTP | Заголовки Hosting: `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, HSTS. CORS — только разрешённые источники |
| Данные пользователя | Гость хранит профиль только в своём браузере. Вошедший пользователь может удалить аккаунт (`DELETE /api/auth/me`). Для гостевого чата — случайный guest id |

**Ограничения безопасности:**
- rate limit хранится в памяти каждого экземпляра функции;
- отдельный аудит безопасности не проводился;
- `VITE_FIREBASE_*` — публичная конфигурация Firebase Web SDK, которая попадает в клиентскую сборку. В `.env.example` ключ Web SDK оставлен пустым: он нужен только для входа через Google.

## 21. Limitations

### Current limitations

1. **Охват.** 91 заведение с фокусом на Казахстан. Программы моделируются 14 категориями направлений, а не отдельными программами вузов.
2. **Актуальность данных.** База собрана вручную 16–19.09.2026 и не обновляется автоматически. Дата сверки отдельной записи не показывается. Часть сроков указана месяцем (метка «ориентировочно»).
3. **Демо-данные.** До прохождения теста интерфейс заполнен вымышленной демо-персоной.
4. **Модель шанса.** Эвристика без валидации на исходах приёма. Возможны крайние значения (до 96 %).
5. **Гостевой режим.** Без входа доступны тест и его результат; кабинет с подбором, сравнением и roadmap требует входа.
6. **Отображение балла.** Процент соответствия на экране ограничен значением 98, поэтому у нескольких сильных вариантов одинаковые 98 %. Порядок списка при этом считается по неограниченному баллу.
7. **Дублирование логики.** Модель соответствия реализована дважды: `shared/logic/match.js` и `src/utils/engine.ts`, веса одинаковые.
8. **Прогресс roadmap.** Отметки подзадач сохраняются в браузере (`localStorage`) и не синхронизируются между устройствами. Задачи и статусы дедлайнов у вошедших пользователей хранятся на сервере.
9. **Список «Мои вузы».** Автоподбор выполняется при прохождении теста; при последующих правках профиля сохранённый список не перезаписывается (подбор, уровни и шансы пересчитываются).
10. **Неиспользуемые в расчётах поля.** TOEFL, ACT, Duolingo, AP («другие экзамены»), уровень английского, интересы и навыки используются только в AI-контексте.
11. **AI.** Нужны ключи и доступность внешних провайдеров. Используются preview-модели Gemini. AI-тексты могут содержать неточности.
12. **Инфраструктура.** Rate limit хранится в памяти экземпляра.
13. **Тесты.** Автоматических тестов нет.

## 23. Judge Test Scenario

Тест и его результат доступны без входа. Для кабинета (шаги 4–10) нужен вход: тестовый аккаунт указан в форме сабмита, также можно зарегистрироваться по e-mail. Точные проценты зависят от всех ответов теста; направление изменений подтверждено контрольным прогоном ([§8](#8-personalization-logic), [§14](#14-testing)).

| Шаг | Action | Expected Result |
|---|---|---|
| **Step 1 — Profile** | Открыть Live Demo → «Пройти тест». Ввести: 11 класс, GPA 4.5 из 5, IELTS нет, направление Computer Science / AI, регионы Казахстан и Европа, бюджет «только грант», вузы не выбирать | Тест проходит 7 шагов с индикатором прогресса |

| **Step 3 — Recommendations** | Посмотреть результат, затем войти в аккаунт | 3 варианта с уровнями Safety / Target / Dream и примерным шансом; после входа полный список — «Вузы → Подбор» (вверху вузы Казахстана и Европы) |
| **Step 4 — Why** | Раскрыть карточку вуза | Причины подбора с реальными значениями профиля, факторы шанса с весами, пороги, дедлайны, ссылка на официальный портал |

| **Step 7 — Roadmap** | «Анализ → План действий» | Шаги по экзаменам, документам, эссе и подаче; подзадачи «Подать заявку» с датами целевых вузов; % выполнения |
