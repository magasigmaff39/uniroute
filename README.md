## 1. Обзор проекта

**UniRoute** — сервис для школьников 9–11 классов из Казахстана, которые поступают в вузы Казахстана и других стран. Отдельные треки есть для поступления в профильные школы (7–8 класс) и колледжи (после 9 класса).

- **Вход.** Пользователь проходит «Тест абитуриента» из 7 шагов: класс, GPA, языковые и вступительные экзамены, олимпиады, специальности, регионы, бюджет, сроки и целевые вузы.
- **Анализ.** Детерминированные правила из `shared/logic` сравнивают профиль с требованиями 91 учебного заведения из базы: оценивают соответствие и примерный шанс, объясняя каждый фактор. Языковая модель (Gemini, при сбое — Groq) добавляет текстовые пояснения и советы.
- **Результат.** Диагностика профиля, ранжированные рекомендации с причинами, сравнение вариантов, персональный roadmap с дедлайнами и один выделенный следующий шаг, у которого можно отмечать прогресс.

**Логика продукта:** `Профиль → Диагностика → Рекомендации → Сравнение → Roadmap → Следующее действие`

**Ценность:** вместо разрозненных сайтов вузов пользователь получает один связный маршрут. Каждый вывод объяснён, а требования и сроки ведут на официальные порталы.

## 3. Проблема

- Требования, экзамены, дедлайны и условия грантов разбросаны по десяткам официальных сайтов. У каждой страны и каждого вуза свои правила.
- Школьнику трудно понять, какие вузы реально подходят его профилю и бюджету и почему.
- Непонятно, что делать дальше: в каком порядке сдавать экзамены, собирать документы и писать эссе, чтобы уложиться в сроки.
- Каталоги вузов и обычные AI-чаты не связывают профиль конкретного ученика с планом действий.

---

## 4. Решение

UniRoute выстраивает цепочку, в которой каждый шаг опирается на предыдущий:

```
Профиль → AI-анализ → Подбор вузов → Объяснение → Сравнение → Roadmap → Задачи → Следующее действие
```

- **Это не чат-бот.** Рекомендации, шансы, roadmap и следующий шаг вычисляются детерминированными правилами из данных профиля. AI-ассистент — дополнительный слой поверх маршрута.
- **Это не каталог.** Список вузов отсортирован под конкретный профиль, к каждому варианту есть причины, а выбранные вузы сразу превращаются в шаги плана с дедлайнами.
- **Результат пересчитывается при изменении вводных:** бюджета, страны, экзамена или специальности (см. [§7](#7-персонализация)).

## 5. Основные функции

Все функции ниже работают в текущей версии.

| Функция | Техническая реализация |
|---|---|
| Тест абитуриента | Пошаговая форма из 7 шагов. Профиль сохраняется в `localStorage` (`admitroute_profile`), а у вошедших пользователей ещё и через `PUT /api/auth/profile` |
| Диагностика профиля | `runDiagnostic()` считает готовность по 4 осям; `POST /api/ai/quick-verdict` добавляет краткий текстовый вердикт |
| Подбор вузов | `matchUniversities()` и `shared/logic/match.js`: балльная модель соответствия (45–98) по 91 учебному заведению; порядок списка: выбранный трек → выбранные регионы → балл → шанс |
| Оценка шансов | `shared/logic/chance.js` → `estimateChance()`: примерная вероятность, уровень Dream / Target / Safety и список факторов с весами |
| Сравнение вузов | `Step5Comparison.tsx`: таблица параметров и AI-разбор различий (`POST /api/ai/compare-insights`) |
| Roadmap | `generateRoadmap()`: разные ветки для школ, колледжей и вузов; для выбранных вузов (до 6) — подзадача с дедлайном и ссылкой на портал |
| Следующее действие и прогресс | `nextStep()` выбирает следующий шаг по профилю для главного экрана; `getNextAction()` находит первую невыполненную подзадачу roadmap. Отметки roadmap сохраняются в браузере (`admitroute_roadmap_progress`), задачи — в `/api/tasks`; статистика задач считается по их списку (есть и отдельный `GET /api/tasks/stats`) |
| Дедлайны | `src/utils/deadlines.ts`: сроки из базы с метками источника; экспорт в календарь `.ics` — `planner/DeadlinesSection.tsx` |
| Стартовые задачи | `POST /api/tasks/generate`: rule-based набор — экзамены по пробелам профиля (IELTS, SAT, ЕНТ), постоянные задачи по документам, эссе и портфолио, задачи подачи для выбранных вузов |
| Гранты и стипендии | Отбор по полям финансирования в базе и бюджету профиля (`cabinet/GrantsSection.tsx`) |
| Олимпиады | 49 олимпиад в базе; rule-based подбор `POST /api/olympiads/recommend`, AI-стратегия `POST /api/olympiads/advice`, избранное |
| Портфолио | CRUD `/api/portfolio`, rule-based оценка по рубрикам (`portfolio.service.js`), AI-оценка и советы (`/evaluate`, `/feedback`) |
| Эссе | Essay Architect: AI-отзыв на черновик (`POST /api/ai/essay-feedback`), ревью эссе в ассистенте (`/essay-review`) |
| Документы | Чек-лист и загрузка PDF, JPG, PNG, WEBP, DOC, DOCX, TXT до 15 МБ с проверкой сигнатуры файла. AI-резюме (только Gemini; PDF, изображения и TXT до 12 МБ) сохраняется в записи документа и используется как контекст AI-ассистента; в интерфейсе не показывается |
| AI-ассистент | Потоковый чат (SSE) после входа: контекст профиля, проверка цифр по контексту, память диалога; без AI-ключей — заготовленный ответ по правилам |
| Новости и соцсигналы вуза | Google News RSS; публичные мета-теги страниц вуза в Instagram, TikTok, YouTube и RSS YouTube-канала; AI-анализ (`/api/universities/:id/news/analysis`, `/social/analysis`) |
| План на e-mail | `POST /api/mail/send-plan`: nodemailer через Gmail SMTP. Работает при заданных `GMAIL_USER` и `GMAIL_APP_PASSWORD`; в текущей конфигурации деплоя адрес отправителя не задан, поэтому отправка отключена (статус — `GET /api/mail/status`) |
| Языки интерфейса | Русский, казахский, английский (`src/i18n`); недостающие строки переводятся через `POST /api/ai/translate` с кешем на 30 дней |
| Авторизация | E-mail и пароль, Google Sign-In (Firebase Auth), опциональный OTP по e-mail |

## 6. Пользовательский путь

1. Открыть лендинг и прочитать, что даёт сервис и какой будет результат.
2. Нажать «Пройти тест» — откроется тест абитуриента.
3. Заполнить 7 шагов профиля. Обязательные поля отмечены, прогресс виден.
4. Получить диагностику: готовность по 4 осям, сильные стороны и риски, AI-вердикт и три предложенных вуза разных уровней (Safety / Target / Dream). До этого шага (и в разделе новостей) сервис работает без входа.
5. Зарегистрироваться — ответы теста сохранятся в аккаунте — и открыть личный кабинет. При входе в уже существующий аккаунт загружается его сохранённый профиль. В разделе «Университеты → Подбор» — вузы, отсортированные по профилю, с объяснением «почему подходит».
6. Открыть карточку вуза: примерный шанс с факторами, требования, дедлайны, официальный портал.
7. Добавить два или более вуза в сравнение и посмотреть разбор различий.
8. Перейти к roadmap («Анализ поступления → План действий»): шаги по экзаменам, документам, эссе и подаче с датами.
9. Увидеть одно выделенное следующее действие: на главном экране и во вкладке «Анализ поступления → Ближайший шаг».
10. Отметить подзадачу выполненной — она зачёркивается, процент плана растёт и сохраняется после перезагрузки; «Ближайший шаг» переходит к следующему этапу, когда выполнены все подзадачи текущего.
11. Изменить ключевой ответ (бюджет, страну, экзамен) — рекомендации, шансы и план пересчитаются.

## 7. Персонализация

**Параметры профиля, которые влияют на результат:**

| Параметр | На что влияет |
|---|---|
| Класс и трек (школа / колледж / вуз) | Категория рекомендуемых заведений и ветка roadmap |
| GPA (шкала 5.0 или 4.0, нормализуется к 4.0) | Соответствие порогу вуза, шанс |
| IELTS / SAT / ЕНТ (есть или нет, балл) | Пороги вуза, шанс, задачи на подготовку к экзаменам |
| Уровень олимпиад (городской / республиканский / международный) | Соответствие селективным вузам, шанс |
| Активности и лидерство | Шанс; больший вес — для США/Канады и вузов с интервью |
| Специальности | Соответствие профилю вуза |
| Регионы (Казахстан, США/Канада, Европа, Азия) | Приоритет вузов в выбранных регионах |
| Бюджет (например `grant_only`, `up_to_5k`) | Финансовая реализуемость, гранты, шанс |
| Целевые вузы и год поступления | Подзадачи roadmap с реальными дедлайнами, даты стартовых задач |
| Мягкие предпочтения (климат, безопасность, питание) | Небольшие бонусы и штрафы к соответствию |

**Поток:** `Ввод (тест) → Обработка (нормализация GPA, правила) → Matching (оценка соответствия каждого вуза) → Рекомендация (сортировка, причины, шанс) → Roadmap (шаги и дедлайны)`

**Как изменение вводных меняет результат** (по коду `shared/logic` и `engine.ts`):

| Изменение | Что происходит |
|---|---|
| Бюджет → «только грант» | У вузов без полного гранта шанс получает фактор −30 («при бюджете $0 поступление нереалистично»); меняются уровни и раздел грантов |
| Сменён регион | Вузы выбранных регионов поднимаются в начало списка «Подбор» и в автоподборе (проверено: при смене Казахстан+Европа → США/Канада вверху UBC, Minerva, UofT, MIT) |
| IELTS не сдан → сдан 7.0 | Фактор IELTS меняется с −18 (у казахстанских школ и колледжей −2) на значение по запасу над порогом: плюс там, где порог ≤ 7.0, и −14 у вузов с порогом 7.5; из стартовых задач пропадает «пробный IELTS» |
| Не сдан ЕНТ при цели в Казахстане | Фактор −15 для казахстанских вузов с порогом ЕНТ; появляется задача «Пробное ЕНТ» |
| Трек «школа» или «колледж» | Другая категория рекомендаций и другая ветка roadmap |
| Выбраны целевые вузы | В roadmap появляются подзадачи «Подать заявку» с дедлайнами и ссылками на порталы |

## 8. AI

### Модели и провайдеры

| Провайдер | Модели (из `server/config.js`) | Роль |
|---|---|---|
| **Google Gemini** (Generative Language API `v1beta`, REST `generateContent` / `streamGenerateContent`) | Три уровня со списками моделей: **fast** — `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite`, …; **smart** — `gemini-3-flash-preview`, `gemini-3.5-flash`, …; **deep** — `gemini-3-flash-preview`, `gemini-3.8-flash`, … | Основной провайдер |
| **Groq** (OpenAI-совместимый API) | `openai/gpt-oss-120b` (для smart и deep), `openai/gpt-oss-20b` (для fast); запасные по списку доступных моделей — `llama-3.3-70b-versatile`, `qwen/qwen3.8-27b`, `llama-3.1-8b-instant` | Резерв при сбое или таймауте Gemini |
| **Groq** | `whisper-large-v3-turbo` | Только эндпоинт `POST /api/ai/transcribe`; в интерфейсе не используется |

Слой `server/services/llm.js` вместе с клиентом `gemini.client.js`:
- перебирает модели уровня;
- временно пропускает сбойную модель: при ошибке 5xx — 10 минут с удвоением до 1 часа, при 429 — 90 секунд, при таймауте — 60 секунд;
- в потоковом режиме, если первый токен не пришёл за 5 секунд, параллельно запускает облегчённую (lite) модель;
- переключается на Groq, если Gemini недоступен;
- разбирает JSON с одной попыткой ремонта.

**Без AI-ключей сервис не падает.** Сервисы возвращают детерминированный результат по правилам (`model: "offline-rules"`), чат отвечает заготовленным сообщением (`localAdvisorFallback`), интерфейс помечает такие блоки как офлайн. Ошибку `503 AI_NOT_CONFIGURED` возвращает только `POST /api/ai/transcribe`. Проверено на чистом клоне репозитория без ключей (19.09.2026).

### Где используется AI

| Функция | Эндпоинт | Уровень | Вход | Выход | Где в UI |
|---|---|---|---|---|---|
| Краткий вердикт | `POST /api/ai/quick-verdict` | fast | Профиль | Вердикт и фокусы | Результат теста |
| Анализ профиля | `POST /api/ai/analyze` | deep | Профиль и контекст | Резюме, сильные и слабые стороны | AI-ассистент |
| Разбор сравнения | `POST /api/ai/compare-insights` | smart | Профиль и выбранные вузы | Различия по измерениям | Сравнение |

### AI и rule-based: разделение

| Rule-based (детерминированно, `shared/logic`, `engine.ts`) | AI (генерация текста) |
|---|---|
| Процент соответствия вуза и сортировка рекомендаций (исключение: AI-анализ профиля в ассистенте может переставить вузы, шанс при этом ограничен расчётным +5) | Формулировки вердиктов, советов и разборов |
| Примерный шанс, уровень Dream / Target / Safety, факторы | Чат-ассистент |

**Контроль качества AI-ответов** (`server/services/chat.service.js`):
- числа и даты в ответе сверяются с переданным контекстом (`unsupportedNumbers`; числа меньше 30 не проверяются); если найдено от 1 до 12 неподтверждённых значений, запускается автоматическая ревизия ответа;
- для казахского языка проверяется доля русских слов;
- если AI-ключи не заданы, ассистент отвечает заготовленным сообщением (`localAdvisorFallback`); при сбое провайдера во время ответа клиент получает событие ошибки.

## 12. Логика рекомендаций

`Профиль → Критерии → Matching → Ранжированный список → Объяснение`

Рекомендации строятся без машинного обучения — это прозрачная балльная модель (`shared/logic/match.js`, `src/utils/engine.ts`).

| Критерий | Вклад в оценку соответствия (база 70) |
|---|---|
| Категория совпадает с треком / не совпадает | +20 / −30 |
| Школа для 7–8 класса, колледж для 9 класса | +15 |
| Специальность входит в сильные направления вуза | +15 |
| Регион выбран пользователем | +10 |
| GPA относительно порога | +10 / +5 / −15 |
| IELTS относительно порога | +8 / +4 / −12 |
| SAT (если вуз его использует) | от +10 до −15 |
| ЕНТ (если у вуза есть порог): ≥ порог + 15 / ≥ порог / не сдан (вуз в Казахстане) | +10 / +5 / −5 |
| Республиканская или международная олимпиада | +15 для вузов с приёмом ≤ 20 %, иначе +6 |
| Климат и питание (по предпочтениям), безопасность района ≤ 5 | от −4 до +4; −3 |
| Бюджет «только грант»: полный грант есть / нет и стоимость > $5 000 | +10 / −40 |
| Бюджет до $5 000: стоимость ≤ $5 000 или есть грант / иначе | +5 / −20 |

- Итог ограничивается диапазоном **45–98 %**. Это **процент соответствия профиля требованиям, а не шанс поступления**. На карточке в «Подборе» рядом с уровнем шанса показан бейдж по этому баллу (High / Medium / Boost Needed).
- **Порядок списка «Подбор»:** сначала заведения выбранного трека, затем выбранных регионов, затем по неограниченному баллу и по шансу. Поэтому смена региона, бюджета или экзамена сразу меняет порядок, даже если у нескольких вузов на экране одинаковые 98 %.
- **Объяснение «почему подходит»** в «Подборе» — текст `whyItFits`. Для 13 заведений в `engine.ts` заданы отдельные тексты, часть из них подставляет значения профиля (GPA, IELTS, ЕНТ, олимпиады); для остальных — описание из базы плюс фраза о бюджете. В карточке вуза добавляются факторы шанса с весами. Краткие причины `fitReasons` (направление, регион, грант, шанс) передаются в контекст AI-вердикта.
- В сравнении и в AI-ассистенте тексты дополнительно формирует AI поверх этих данных.

## 13. Оценка шансов и профиля

`shared/logic/chance.js` → `estimateChance(profile, university)`:

1. **База.** Берётся из доли принятых: `p = clamp(8 + acceptanceRate × 0.9, 5, 85)`.
2. **Факторы с весами.** GPA от +12 до −25; IELTS от +10 до −28; SAT от +14 до −24; ЕНТ от +16 до −18; олимпиады от +22 до −6; активности от +12 до −10 (с большим весом для США/Канады и вузов с интервью); специальность +4 / −8; финансы, например −30 при бюджете $0 и отсутствии полного гранта.
3. **Итог.** `p = clamp(p + Σфакторов × (p < 30 ? 0.7 : 1), 2, 96)`, уровни: **Dream** < 30 %, **Target** 30–59 %, **Safety** ≥ 60 %.
4. **Проекции.** `estimateWithProjections` показывает, как изменится оценка при целевом балле IELTS, SAT или ЕНТ (в карточке вуза).

Пользователь видит каждый фактор с текстовым пояснением, например «IELTS 6.5 ниже порога 7 на полбалла». В карточке вуза и сравнении значение подписано «Примерный шанс».

> **Важно.** Это эвристическая оценка по опубликованным порогам и доле принятых. Она не обучена и не проверена на реальных исходах приёма и **не является гарантией или точной вероятностью поступления**. Решение всегда принимает вуз.

**Диагностика профиля** (`runDiagnostic`) считает готовность по 4 осям — академика, язык, портфолио, финансы — и выделяет сильные стороны и риски.

## 15. Безопасность и приватность

Ниже перечислены только меры, которые реально есть в коде.

- **Секреты.**
  - Ключи (`GEMINI_API_KEY`, `GROQ_API_KEY`, `GMAIL_APP_PASSWORD`) хранятся в `.env` локально и в Firebase Secret Manager в production (`defineSecret` в `server/firebase.js`).
  - `.env*` и `functions/.secret.local` исключены через `.gitignore`.
  - В репозитории есть только `.env.example` без секретных значений.
- **Firestore.** Правила запрещают любой прямой доступ клиента (`allow read, write: if false`). Все операции идут через сервер и Admin SDK.
- **Пароли.** Хешируются scrypt со случайной 16-байтной солью и сравниваются через `timingSafeEqual`.
- **Сессии.**
  - Токен: случайные 256 бит (`randomBytes(32)`), в БД хранится только SHA-256 хеш.
  - Срок жизни 30 дней; токен передаётся только в заголовке `Authorization: Bearer`.
- **Google Sign-In.** ID-токен проверяется на сервере через `verifyIdToken(idToken, true)` с проверкой отзыва.
- **OTP.** Коды хранятся в виде SHA-256 хеша и сравниваются через `timingSafeEqual`. По умолчанию OTP не обязателен (`OTP_REQUIRED`).
- **Rate limiting.** Лимиты в минуту по IP и пользователю: общий 240, AI 30, auth 20, upload 30.
- **Загрузка файлов.**
  - Разрешён только белый список MIME-типов, и тип сверяется с сигнатурой файла (magic bytes).
  - Размер файла — до 15 МБ.
  - Пути хранения нормализуются (`safeStoragePath`, без `..`).
- **HTTP-заголовки (Hosting).** `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, `Strict-Transport-Security`.
- **CORS.** В production разрешены настроенные источники, домены `*.web.app`, `*.firebaseapp.com`, `*.vercel.app` и запросы без заголовка Origin; в режиме разработки — любые источники.
- **Данные пользователя.**
  - Профиль гостя хранится в браузере (`localStorage`). Для AI-вердикта профиль (включая имя и возраст) передаётся на сервер и AI-провайдеру (Gemini или Groq); сам вердикт сохраняется в коллекции `ai_analyses` без привязки к пользователю.
  - Удаление аккаунта есть в API (`DELETE /api/auth/me`), кнопки в интерфейсе нет; загруженные файлы документов, память чата и отзывы об ответах при удалении не стираются.
  - API поддерживает гостевой guest id для чата; в интерфейсе чат доступен после входа.
- **Открытые эндпоинты.** AI-эндпоинты (`/api/ai/*`) и `POST /api/mail/send-plan` доступны без входа и защищены только rate limit. `GET /api/health` и `GET /api/mail/status` публичны; при настроенной почте они показывают адрес отправителя.
- **Состояние аудита.** Отдельный аудит безопасности не проводился.

## 18. Локальный запуск

**Требования**
- Node.js **22.x** (`engines` в `package.json`). Для локальной БД нужен встроенный `node:sqlite` — рекомендуется Node ≥ 22.13.
- npm.
- Необязательно: ключи Gemini и/или Groq для AI-функций, Firebase-проект для Google Sign-In и деплоя.

**Установка и запуск в режиме разработки**

```bash
npm install
cp .env.example .env    # в Windows PowerShell: Copy-Item .env.example .env
npm run dev             # клиент http://localhost:5173 + API http://127.0.0.1:3001
```

Vite проксирует `/api` на `http://127.0.0.1:3001`. Без AI-ключей всё работает: AI-функции переходят на ответы по правилам и помечаются как офлайн.

**Production-сборка локально**

```bash
npm run build
npm start               # при NODE_ENV=production в .env Express отдаёт dist/ и API на http://127.0.0.1:3001
```

Для такого запуска добавьте в `.env` строки `NODE_ENV=production` и `CORS_ORIGINS=http://127.0.0.1:3001`: в production-режиме CORS пропускает только перечисленные источники. В режиме `NODE_ENV=development` сервер отдаёт только API, а интерфейс открывается через `npm run dev`.

**Деплой в Firebase**

```bash
npm run secrets:set     # переносит ключи из .env в Secret Manager
npm run deploy          # hosting + functions + firestore rules
```

**Переменные окружения** (`.env.example`; значения **никогда** не коммитятся)

| Переменная | Назначение |
|---|---|
| `API_PORT`, `HOST`, `NODE_ENV` | Порт (по умолчанию 3001), хост и режим API |
| `GEMINI_API_KEY` | Ключ Google Gemini (основной AI) |
| `GROQ_API_KEY` | Ключ Groq (резервный AI) |
| `FIREBASE_PROJECT_ID`, `FIREBASE_SERVICE_ACCOUNT` (опц.) | Firebase-проект; service account включает Firestore вне облака |
| `DB_DRIVER` | `sqlite` или `firestore` (по умолчанию выбирается автоматически) |
| `FILE_STORAGE` | `local`, `gcs` или `firestore` |
| `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID` | Публичная конфигурация Firebase Web SDK (Google Sign-In) |
| `VITE_API_URL` (опц.) | Абсолютный URL API для production-сборки |
| `GMAIL_USER`, `GMAIL_APP_PASSWORD` | SMTP для OTP и отправки плана |

## 22. Известные ограничения

- **Данные.**
  - База охватывает 91 учебное заведение и собрана вручную.
  - Данные собраны 16–19.09.2026; пороги, доля принятых и дедлайны кампании 2026/27 нужно сверять с официальными порталами (ссылка есть у каждой записи).
  - Дата сверки отдельной записи в интерфейсе не показывается.
- **Оценка шансов.** Это эвристика без валидации на реальных исходах приёма, а не точная вероятность.
- **Разные метрики на экранах.** Процент **соответствия** в рекомендациях (45–98, бейдж High / Medium / Boost Needed) и примерный **шанс** с уровнем Dream / Target / Safety — разные величины. Например, вуз может показывать «98 % соответствия · High» и одновременно уровень Dream. Пользователь может их перепутать.
- **Почта.** Отправка плана и OTP реализована, но в текущей конфигурации деплоя адрес отправителя (`GMAIL_USER`) не задан, поэтому письма не отправляются. Регистрация от этого не зависит: подтверждение кодом выключено.
- **Тексты AI.** Ответы языковой модели могут содержать неточности. В статических текстах сервиса формулировки о «гарантиях» и неподтверждённая статистика убраны, а в описаниях сильных сторон приводятся реальные подсчёты по базе.
- **Зависимость от AI.**
  - Вердикты, разборы и чат требуют ключей и доступности Gemini или Groq. Лимиты и таймауты провайдеров влияют на скорость.
  - Используются preview-модели Gemini, список моделей может потребовать обновления.
- **Rate limiting.** Лимит хранится в памяти каждого экземпляра функции и не распределён между экземплярами.
- **Файлы в production.** Документы хранятся в Firestore частями (`FILE_STORAGE=firestore`); загрузка файлов, близких к лимиту 15 МБ, в production не проверялась.
- **Удаление аккаунта.** Доступно только через API, кнопки в интерфейсе нет; файлы документов при удалении не стираются.
- **Гостевой режим.** Без входа доступны тест и его результат; кабинет с подбором, сравнением и roadmap требует входа. Профиль гостя хранится только в `localStorage`. Профиль по умолчанию до теста — демо-персона.
- **Тестирование.** Нет автоматических тестов (см. [§16](#16-тестирование)).
- **Прогресс roadmap.** Отметки подзадач сохраняются в браузере и не синхронизируются между устройствами. Задачи и статусы дедлайнов у вошедших пользователей хранятся на сервере.
- **Отображение балла.** Процент соответствия ограничен значением 98, поэтому у нескольких сильных вариантов на экране одинаковые 98 %. Порядок списка при этом считается по неограниченному баллу.
- **Список «Мои вузы».** Автоподбор трёх вузов выполняется при прохождении теста; при правке профиля сохранённый список не перезаписывается (меняются подбор, уровни и шансы).
- **Дублирование логики.** Модель соответствия реализована в `shared/logic/match.js` и `src/utils/engine.ts` с одинаковыми весами.
- **Неиспользуемый код.**
  - `POST /api/ai/transcribe` (голосовой ввод) и `POST /api/ai/compare` реализованы на сервере, но не используются в UI.
  - Модель `groq/compound` задана в конфигурации, но не вызывается.
- **Напоминания.** Push- и e-mail-напоминаний о дедлайнах нет: есть только разовая отправка плана и экспорт `.ics`.

## 24. Проверяемость и прозрачность

- **Воспроизводимость.** Рекомендации, шансы, roadmap и следующее действие — детерминированные функции в `shared/logic` и `src/utils/engine.ts`. Один и тот же профиль всегда даёт один и тот же результат, и его можно проверить по коду.
- **Объяснимость.** У каждой рекомендации и оценки шанса есть видимые факторы с весами и текстом.
- **Источники.**
  - У каждого вуза есть ссылка на официальный портал.
  - У каждого дедлайна есть метка источника: официальный, рекомендованный, ориентировочный или пользовательский.
  - Новости ведут на исходные публикации.
- **Разделение AI и правил.** Ранжирование, шансы, roadmap и следующий шаг считают правила; AI пишет пояснения поверх их результатов. Исключение — AI-анализ профиля в ассистенте: модель может переставить вузы, но шанс не выше расчётного +5. В ответах AI-эндпоинтов есть поле `model` (провайдер и модель), в событиях чата — ещё и `provider`.
- **Контроль AI.** Числа в ответе ассистента сверяются с контекстом, неподтверждённые значения запускают ревизию ответа.
- **Без выдуманных метрик.** В README и продукте не заявляются пользователи, выручка или точность, подтверждённые измерениями. Ограничения перечислены в [§22](#22-известные-ограничения).
- **История разработки.** Проект создан командой DoStar 16–19.09.2026. Первые 11 коммитов (16–17.09.2026, авторы Magzhan и Raul) перенесены из исходного репозитория команды [magasigmaff39/maga](https://github.com/magasigmaff39/maga); финальные изменения — коммитами от 19.09.2026.
